## 📖 Intro (Kya hai Metadata & SEO?)

Jab tum koi website kholte ho aur usse **Google** pe search karte ho, toh search result mein jo **blue title** aur **chhota description** dikhta hai — woh kahan se aata hai? 🤔

Woh aata hai **`<head>` section** ke HTML tags se:

```html
<head>
  <title>Learn Metadata In Nextjs</title>
  <meta name="description" content="Generated by create next app" />
  <link rel="icon" href="/favicon.ico" />
  <meta property="og:title" content="Learn Metadata In Nextjs" />
  <meta property="og:image" content="https://example.com/og.png" />
</head>
```

**Metadata** = page ke baare mein browser, search engine (Google/Bing) aur social media (WhatsApp/Twitter/LinkedIn) ko batane wala data.

**SEO (Search Engine Optimization)** = taaki tumhara page Google ke **top pe rank** kare.

Next.js (App Router) humein yeh sab **declare karne ka modern tarika** deta hai — na ki manually `<head>` mein tags likhne padte hain. Next.js **server-side** par automatically sahi `<head>` generate kar deta hai. 🔥

### ⚡ 3 Faayde (Why should we care?)
1. **SEO** — Google ko page samajh aata hai → ranking badhti hai
2. **Social Sharing** — WhatsApp/Twitter/LinkedIn pe link share karo toh **rich preview card** dikhta hai
3. **Branding** — Favicon (tab pe chhota icon) se brand identity banti hai

## 🧠 Metadata — The Core Concept

Next.js mein metadata do tarike se set kar sakte ho:

| Tarika | Kab use karo | Example |
|--------|--------------|---------|
| **`export const metadata`** | Static data (hardcoded) | `title`, `description` |
| **`export async function generateMetadata()`** | Dynamic data (API/params se) | Blog title from DB |

> ⚠️ **Zaroori Rule:** Metadata **sirf Server Components** mein chalta hai. Client component (`'use client'`) mein metadata export **nahi** kar sakte — woh error dega.

---

## 1️⃣ Root Metadata (layout.js)

Sabse pehle `app/layout.js` mein root level ka metadata define karte hain. **Layout nested hota hai**, isliye yeh metadata **poore app** mein apply hota hai.

```js
// app/layout.js
export const metadata = {
  title: "Learn Metadata In Nextjs",
  description: "Generated by create next app",
};

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

**Result (browser tab mein):**
```
┌──────────────────────────────────────────┐
│  ⓘ Learn Metadata In Nextjs        _ □ ✕ │
└──────────────────────────────────────────┘
```

### 🔁 Metadata Inheritance Tree

```
app/layout.js  (root)
│   title: "Learn Metadata In Nextjs"
│
├── app/page.js               → inherits root title
│
├── app/about/page.jsx        → OVERRIDE: "Welcome To About Page"
│
└── app/dashboard/layout.jsx  → title: { default, template }
    │
    ├── dashboard/page.jsx          → "Welcome To Dashboard Page"
    ├── dashboard/settings/page.jsx → absolute: "Setting Page"
    └── dashboard/user/[userId]     → generateMetadata → "User 123"
```

> **Concept:** Child page apna `metadata` define kare toh parent ka **override** ho jaata hai. Agar child ne kuch define nahi kiya, toh parent ka **inherit** hota hai.

## 2️⃣ Static Metadata (Page-Level)

Jab data **hardcoded** ho, bas `metadata` object export karo:

```js
// app/about/page.jsx
export const metadata = {
  title: "Welcome To About Page",
  description: "Generate By Neeraj",
};

const AboutPage = () => {
  return <div>AboutPage</div>;
};

export default AboutPage;
```

Ab jab user `/about` kholta hai, tab title ban jaata hai **"Welcome To About Page"** (root ka override).

---

## 3️⃣ Dynamic Metadata (generateMetadata)

Jab title **data pe depend** karta ho (jaise URL params, database, API), tab `generateMetadata` use karte hain — yeh ek **async function** hai jo render se pehle chalta hai.

```js
// app/dashboard/user/[userId]/page.jsx
export async function generateMetadata({ params }) {
  const { userId } = await params;   // Next 15+: params ABHI BHI async hai
  return {
    title: `User ${userId}`,
    description: `Profile Page For User ${userId}`,
  };
}

const UserIdPage = async ({ params }) => {
  const { userId } = await params;
  return <div>UserIdPage: {userId}</div>;
};

export default UserIdPage;
```

**Output (URL: `/dashboard/user/42`):**
- Title → `User 42`
- Description → `Profile Page For User 42`

### ⚠️ Next.js 15/16 Ka Important Change
Pehle `params` ek **plain object** tha. Ab woh **Promise** ban gaya hai, isliye `await params` **zaroori** hai. Yeh mistake beginners sabse zyada karte hain!

### 🗺️ Dynamic vs Static Flow Diagram

```
        ┌─────────────────────────────────────────┐
        │         Request: /dashboard/user/42      │
        └────────────────────┬────────────────────┘
                             │
                             ▼
              ┌──────────────────────────────┐
              │  Next.js routing decide karta │
              │  hai kaunsa page render hoga  │
              └──────────────┬───────────────┘
                             │
              ┌──────────────┴───────────────┐
              │                              │
     ┌────────▼─────────┐         ┌──────────▼──────────┐
     │ STATIC metadata   │         │ DYNAMIC metadata    │
     │ (export const)    │         │ (generateMetadata)  │
     │ • Hardcoded       │         │ • params/API se     │
     │ • Fast (no await) │         │ • await karna padta │
     │ • about, settings │         │ • [userId], blogs   │
     └────────┬─────────┘         └──────────┬──────────┘
              │                              │
              └──────────────┬───────────────┘
                             ▼
              ┌──────────────────────────────┐
              │  <head> automatically banta   │
              │  hai with title/description   │
              └──────────────────────────────┘
```

## 4️⃣ Title Metadata — 3 Powerful Forms (`default`, `template`, `absolute`)

`title` ko hum **string** ki jagah **object** bhi bana sakte hain. Yeh bahut powerful hai jab multiple pages ka title **consistent** rakhna ho.

### 📌 a) `default` + `template` (Layout mein)

```js
// app/dashboard/layout.jsx
export const metadata = {
  title: {
    default: "Welcome To Dashboard Page",
    template: "%s | Dashboard Layout",
  },
  description: "Generate By Neeraj",
};
```

- **`default`** → jab page khud koi title na de, tab yeh lagega
- **`template`** → `%s` ko child ka title se replace kar deta hai

**Result:**
| Route | Final Title |
|-------|-------------|
| `/dashboard` | `Welcome To Dashboard Page` (default) |
| `/dashboard/user/5` | `User 5 \| Dashboard Layout` (template applied) |

### 📌 b) `absolute` (Template ko bypass)

```js
// app/dashboard/settings/page.jsx
export const metadata = {
  title: {
    absolute: "Setting Page",
  },
  description: "Welcome to settings page.",
};
```

Jab kisi page ko **parent ka template bilkul na chahiye** ho, tab `absolute` use karo.

**Result:** `/dashboard/settings` → sirf **`Setting Page`** (bina `| Dashboard Layout` ke!)

### 🧩 Title Resolution Diagram

```
Child ne title diya?
        │
        ├── ❌ Nahin diya  ──────────► template.title.default (parent)
        │
        ├── ✅ { absolute: "X" } ────► "X"  (template IGNORED)
        │
        └── ✅ "Y" (string) ─────────► template.replace("%s", "Y")
                                        → "Y | Dashboard Layout"
```

> **Pro Tip:** `template` sabse zyada **nested layouts** mein kaam aata hai — jaise `/dashboard/*` ke saare pages ka title automatically `XYZ | Dashboard Layout` ban jaata hai. Ek-ek karke har page mein likhne ki zaroorat nahi!

## 5️⃣ Favicons

Favicon woh **chhota icon** hota hai jo browser tab, bookmarks aur Google search result mein dikhta hai.

Next.js mein **File Conventions** use hote hain — bas file ko sahi naam se `app/` folder mein rakh do, Next.js khud handle kar lega:

```
app/
├── favicon.ico          auto-detect → <link rel="icon" />
├── icon.png             auto → <link rel="icon" />
├── apple-icon.png       auto → <link rel="apple-touch-icon" />
└── opengraph-image.png  auto → <meta property="og:image" />
```

Is repo mein **`app/favicon.ico`** present hai, isliye har page pe automatically favicon lag jaata hai — **koi extra code nahi chahiye!**

### Manual tarike (agar file convention na use karo)

```js
// layout.js mein
export const metadata = {
  icons: {
    icon: "/favicon.ico",
    apple: "/apple-touch-icon.png",
  },
};
```

ya phir Image Response se (dynamic favicon):

```js
// app/icon.jsx  → dynamically generate favicon
import { ImageResponse } from "next/og";

export default function Icon() {
  return new ImageResponse(
    (
      <div style={{ fontSize: 64, background: "black", color: "white" }}>
        🚀
      </div>
    ),
    { width: 64, height: 64 }
  );
}
```

## 6️⃣ Open Graph Images (Static & Dynamic)

**Open Graph (OG) Protocol** woh standard hai jo decide karta hai ki tumhara link **WhatsApp/Twitter/LinkedIn/Facebook** pe share karne par kaisa **preview card** dikhega.

```html
<!-- Yeh tags automatically generate hote hain -->
<meta property="og:title" content="Learn Metadata In Nextjs" />
<meta property="og:description" content="Generated by create next app" />
<meta property="og:image" content="https://mysite.com/og.png" />
```

### 🖼️ Static OG Image (Simple)

Sabse aasan tarika — ek PNG file `app/` mein rakho:

```
app/
└── opengraph-image.png    → Next.js auto isse og:image bana dega
```

ya manually:

```js
export const metadata = {
  openGraph: {
    title: "Learn Metadata In Nextjs",
    description: "Next.js mein metadata seekho",
    images: ["/opengraph-image.png"],   // absolute URL hona chahiye
    url: "https://mysite.com",
    siteName: "My Learning Repo",
    type: "website",
  },
};
```

### ⚡ Dynamic OG Image (`opengraph-image.jsx`)

Har blog/product ka **unique OG image** chahiye? `next/og` package se **code se image banao** — koi Photoshop nahi!

```js
// app/blog/[slug]/opengraph-image.jsx
import { ImageResponse } from "next/og";

export const size = { width: 1200, height: 630 };
export const contentType = "image/png";

export default async function Image({ params }) {
  const { slug } = await params;

  return new ImageResponse(
    (
      <div
        style={{
          fontSize: 80,
          width: "100%",
          height: "100%",
          display: "flex",
          alignItems: "center",
          justifyContent: "center",
          background: "linear-gradient(135deg, #667eea 0%, #764ba2 100%)",
          color: "white",
        }}
      >
        {slug}
      </div>
    ),
    size
  );
}
```

**URL:** `/blog/nextjs-16` → OG image mein dikhega **"nextjs-16"**

## 7️⃣ Metadata Kaise Kaam Karta Hai? (Under the Hood)

```
┌────────────────────────────────────────────────────────┐
│                    Next.js Build/Request                │
│                                                         │
│  1. Route match:  /dashboard/user/42                    │
│                          │                              │
│  2. Layout chain resolve:                               │
│     root layout → dashboard layout → page              │
│                          │                              │
│  3. Metadata collect:                                    │
│     • root: title "Learn Metadata In Nextjs"            │
│     • dashboard: template "%s | Dashboard Layout"       │
│     • page: generateMetadata() → { title: "User 42" }  │
│                          │                              │
│  4. MERGE + RESOLVE:                                    │
│     template applied → "User 42 | Dashboard Layout"     │
│                          │                              │
│  5. Render <head> HTML → server response                │
│     <title>User 42 | Dashboard Layout</title>           │
│     <meta name="description" ...>                       │
│     <link rel="icon" href="/favicon.ico" />             │
│     <meta property="og:title" ...>                      │
└────────────────────────────────────────────────────────┘
```

**Key Point:** Yeh sab **server par** hota hai, isliye Google crawler aur social bot ko **perfect HTML** milta hai (client-side JS chalne ka wait nahi karna padta). Yehi Next.js ka **superpower** hai traditional React apps ke mukable.

## 8️⃣ Middleware (Bonus — naam mein hai toh cover kar lete hain)

Middleware request ke **bina render hue**, server par chalta hai — auth check, redirect, header set wagera ke liye.

```js
// middleware.js  (project root mein)
import { NextResponse } from "next/server";

export function middleware(request) {
  const token = request.cookies.get("token")?.value;

  // Agar logged-in nahi ho aur dashboard access kar rahe ho → /login pe bhejo
  if (request.nextUrl.pathname.startsWith("/dashboard") && !token) {
    return NextResponse.redirect(new URL("/login", request.url));
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/dashboard/:path*", "/settings/:path*"],
};
```

### 🗺️ Middleware Flow

```
Incoming Request
      │
      ▼
┌──────────────┐   NO match    ┌────────────────────┐
│  matcher     │──────────────►│  Seedha page render │
│  match hua?  │               └────────────────────┘
└──────┬───────┘
       │ YES
       ▼
┌──────────────────┐
│  middleware()     │──── token nahi? ──► redirect /login
│  chalta hai       │
└────────┬─────────┘
         │ token hai
         ▼
┌────────────────────┐
│  Page render +      │
│  metadata <head>    │
└────────────────────┘
```

> **Note:** Is repo mein abhi `middleware.js` file **maujood nahi hai** — upar wala code copy karke root mein bana sakte ho practice ke liye. Middleware aur metadata dono **alag-alag layers** hain: middleware request pehle handle karta hai, metadata response ke `<head>` mein jaata hai.

## 9️⃣ Real-Life Usages

| Real Website | Kya use karta hai | Concept |
|--------------|-------------------|---------|
| **Amazon / Flipkart** | Har product page ka **unique title + OG image** | `generateMetadata` + dynamic OG |
| **Medium / Dev.to** | Blog ka title + author + cover image share card | `openGraph` object |
| **Netflix** | Har show ka custom OG image (poster + title) | Dynamic `opengraph-image.jsx` |
| **Swiggy / Zomato** | Restaurant page ka SEO title | `generateMetadata` from API |
| **LinkedIn** | Post share pe rich card | `twitter` + `openGraph` metadata |
| **SaaS Dashboards** | Auth-protected routes | `middleware.js` |

### 📦 Ek Asli Example: E-commerce Product Page

```js
// app/products/[id]/page.jsx
export async function generateMetadata({ params }) {
  const { id } = await params;
  const res = await fetch(`https://api.store.com/products/${id}`);
  const product = await res.json();

  return {
    title: `${product.name} — Buy Online`,
    description: product.shortDesc,
    openGraph: {
      title: product.name,
      images: [product.imageUrl],   // real product photo
    },
  };
}
```

Ab jab user yeh product link **WhatsApp pe share** karega, toh dost ko product ki **photo + naam + price** rich card mein dikhega — click-through rate **3-4x** badh jaata hai!

## ✅ Quick Revision Cheat-Sheet

```
📄 Static Metadata     → export const metadata = { ... }
⚡ Dynamic Metadata    → export async function generateMetadata({ params })
🧵 title.default       → fallback title (layout mein)
🧵 title.template      → "%s | SiteName" (child title inject)
✂️ title.absolute      → template ko bypass
🖼️ Favicon             → app/favicon.ico (auto)
📸 Static OG           → app/opengraph-image.png (auto)
🎨 Dynamic OG          → app/opengraph-image.jsx + next/og
🔀 Middleware           → request se pehle chalta hai (auth/redirect)
```

### 🚫 Common Mistakes (Bach ke rehna!)
1. `generateMetadata` mein `params` ko `await` karna **bhool jaana** (Next 15/16)
2. `og:image` dena **relative path** — social crawler load nahi kar paata
3. Client component (`'use client'`) mein metadata export karna → **error**
4. `template` ka `%s` likhna bhool jaana
5. Metadata ko **`getServerSideProps`** se compare karna (woh Pages Router hai, App Router mein nahi)
